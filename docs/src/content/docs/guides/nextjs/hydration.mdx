The server container never crosses the React Server Component boundary. Transfer
only a serializable snapshot and restore it into a separate client-safe
container.

```txt
server state -> serializable snapshot -> client state
```

`dehydrate` and `hydrate` live in the framework-agnostic `di-craft/hydration`
entry point. `di-craft/next/server` re-exports `dehydrate`, and
`di-craft/next/client` re-exports `hydrate`, so Next.js apps can import them
from either place.

<Steps>

1. Make the state hydratable

   Implement `Hydratable<TSnapshot>` with a serializable snapshot type.

2. Define a typed hydration schema

   ```ts
   const hydration = {
     user: USER_STATE,
   } satisfies HydrationSchema;
   ```

3. Create the server snapshot

   ```ts
   const snapshot = dehydrate({
     container: getRequestContainer(),
     schema: hydration,
   });
   ```

4. Restore it on the client

   ```ts
   hydrate({
     container: clientContainer,
     schema: hydration,
     snapshot,
   });
   ```

</Steps>

## Keep snapshots raw and minimal

Serialize response-level data — the shape your services received — instead of
derived, normalized records. Derived state is often several times larger than
the raw payload it came from, and the client can recompute it. Send the state a
boundary needs, not every state the container holds, and let each snapshot
cross the boundary exactly once.

## Stream partial snapshots

For streamed UI, hydrate incrementally. Define one schema per Suspense
boundary, dehydrate each boundary's schema where it renders on the server, and
hydrate it on the client as soon as its snapshot arrives:

- Schemas are independent: hydrating one boundary never touches another
  boundary's tokens.
- Hydrating the same token again applies the newer snapshot as an update.

## Hold snapshots for late consumers

A streamed snapshot can arrive before the component that needs it mounts: a
dialog or tab opened seconds after the page rendered still wants the data the
page already received. `createSnapshotBus` parks delivered snapshots for a
short time — 30 seconds by default — so late consumers hydrate without
refetching:

```ts
const snapshots = createSnapshotBus();

// When the streamed snapshot arrives:
snapshots.push(conversationSchema, snapshot);

// When a dialog mounts later:
const cached = snapshots.pull(conversationSchema);
if (cached !== undefined) {
  hydrate({
    container: clientContainer,
    schema: conversationSchema,
    snapshot: cached,
  });
}
```

- The schema object is the key, so share one stable schema reference between
  the pushing and pulling code.
- Pulling does not remove the entry; several late consumers can hydrate from
  one snapshot. Pushing again replaces it and resets the time to live.
- Expiration is lazy and the bus never schedules timers, so it is safe in
  every runtime. Pass `ttl` (milliseconds) to change that window, or a `now`
  clock to make expiration deterministic in tests.
