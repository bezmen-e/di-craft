The suite compares `di-craft` with InversifyJS, Awilix in PROXY and CLASSIC
modes, TSyringe, TypeDI, and Typed Inject. Every subject receives equivalent
plain-TypeScript object graphs and lifecycle assertions before measurement.

## Methodology

- The production ESM build is measured, not package source.
- Each subject runs in a fresh Bun process to isolate module caches, global
  container state, garbage collection history, and JIT history.
- A complete public run uses 14 balanced rounds so every one of the seven
  subjects appears in every launch position twice and predecessor effects are
  balanced.
- Tinybench measures batched operations. Reports normalize batch duration to
  nanoseconds per DI operation, then aggregate rounds with the median and median
  absolute deviation (MAD).
- Unsupported capabilities remain `N/A`; the runner does not substitute a
  semantically different operation.

These are synthetic dependency-injection operations, not whole-application
speedups. Treat small differences as machine- and runtime-sensitive, and use the
raw result when reproducing or auditing a claim.

## Run it yourself

From the repository root:

```bash
bun run benchmarks:precondition
bun run benchmarks:quick
bun run benchmarks:public
```

Quick mode is for local feedback and cannot update published documentation. See
the [benchmark workspace on GitHub](https://github.com/bezmen-e/di-craft/tree/main/benchmarks)
for the full scenario definitions and reporting commands.
